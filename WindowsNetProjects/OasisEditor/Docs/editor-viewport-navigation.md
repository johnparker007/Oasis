# Editor viewport navigation

Editor viewports use mouse-wheel, cursor-centred zoom and middle-mouse drag to pan. `Fit` calculates the current content-to-viewport scale, centres the content, and clears pan. Fit is an action, not the meaning of 100%.

For every raster-backed view, **100% means reference-artwork Actual Pixels**: one pixel in the displayed source region maps to one physical output pixel where platform alignment permits. Logical document coordinates remain authored geometry; the viewport first converts them through the reference raster's X/Y pixels-per-logical-unit density. A vector/logical-only document with no usable reference raster falls back to one logical unit per physical pixel. Zoom percentages describe reference-raster magnification and are never relative to Fit.

Viewport state is transient editor state. Zooming, panning, fitting, and pointer-status updates are not persisted or undoable, do not dirty authored content, and must not invoke image processing or builds.

The compact bottom status bar contains content dimensions, cursor coordinates or contextual status, Fit, and an editable zoom percentage/control. Coordinates use the host's content space and show a neutral placeholder outside its meaningful bounds. The zoom tooltip identifies raster Actual Pixels or logical-unit semantics without adding explanatory status text.

The adopted views are primary and Override Artwork Geometry, Panel2D edit, and the shared logical Face edit surface used by Layout, Components, Illumination, and calibration destinations. Panel2D uses the first valid Background image's raster dimensions divided by that element's logical dimensions; without one it uses the 1:1 fallback. Face uses the artwork image actually displayed (including a high-resolution override): the displayed, provenance-cropped source rectangle's raster dimensions are divided by the `FaceArtworkElement` destination dimensions. Face bounds and component coordinates remain in canonical logical Face space. If X/Y densities materially differ, the existing non-uniform artwork mapping is preserved; one percentage cannot make intentionally stretched source pixels square.

Fit uses the logical bounds multiplied by reference density, current viewport size, and current DPI, then centres content and clears pan. Thus its displayed percentage is based on the displayed raster extent rather than arbitrary logical dimensions. Non-zero Panel2D origins are retained. Explicit percentages and resize do not activate a persistent Fit mode. At 100% reference-raster magnification and above, primary artwork/background rasters use nearest-neighbour sampling; vector overlays, handles, and text retain their normal policies.

WPF layout and mouse positions are DIPs, whereas `SKElement` paint canvases use physical surface pixels. Navigation therefore uses a DIP transform, while the centralized renderer adapter multiplies its origin by the current per-monitor DPI and applies physical X/Y scales. A DPI refresh changes only that transient bridge: the user-visible percentage and authored state remain unchanged.
